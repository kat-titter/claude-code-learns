# Metacognition

Work teaches something every time; this skill makes the lesson visible, links it to the rest of the work, and lets the
pieces echo one another. Four moves, in the order work runs: notice what you are learning (§1), connect it to what other
documents and projects already know (§2), carry the connection inside the work as a resonance a reader can find (§3),
and keep the link so the next piece starts from it (§4). Each move feeds the next: a lesson named in a line can be
matched across projects, a match found can be echoed, an echo recorded is found again.

## Gotchas

- A lesson learned in one project gets taught again in its sibling ("always have legend, prefer position under plot"
  for a pitch deck on 2026-10-26: "remember, legend should go below plot" for a DJ studio the next
  day): when feedback lands, ask which sibling projects it also fits, and apply it there before being asked (§2).
- The same mistake can land twice in one day from two projects (an accent worn outside its meaning: gold in an art piece's
  basin feed, then pink in a pitch deck, 2026-10-26): before starting, read what the sibling just learned (§2).

## 1. Notice: what am I learning?

- **Ask at three moments**: after a surprise (a result off from the guess), after a correction (the person says no, or
  "remember"), and before the reply. Each answer is one line, written as a finding, not a diary: "a legend placed below
  the plot reads first in every project that has asked", not "worked on legends".
- **Three kinds of lesson, kept apart**: about the domain (a fact: in a cell-painting deck, "normal" means published
  images plus the lab's past data), about the method (a step that worked: measure text baselines, not box centres),
  about the person (a taste: three colours at most). Each kind has a different home (§4).
- **Say it in the reply** when the task taught something worth keeping: one closing line, "Learned: X (also fits Y)".
  A task that taught nothing new says nothing.

## 2. Connect: where else is this true?

- **Look sideways before starting.** Read the memory index and the notes of sibling projects for the same shape: a
  mechanism, a structure, a word, a figure form. Name the shared shape in one phrase.
- **Test the match on the mechanism, not the word.** A connection holds when the same thing happens in both places: an
  installation's water cycle and a learning loop both return their output to their input, so they share one structure
  (the person's full threads live in their style skill, §4). Two things that only share a name ("drop" of water, "drop"
  in a set) are a pun: keep it light.
- **Borrow across the match**: a fix, a method or a form that worked in one place is tried in the other (a flow-cytometry
  gate for picking songs, chemical safety signs for warnings, a contribution grid for coverage). Say the source in one
  line so the borrowing can be checked.
- **Carry lessons forward on purpose**: when feedback lands in one project, list the sibling projects it also fits and
  apply it there, or propose it in one line.

## 3. Carry: let the work echo

A resonance is a motif, a number, a word or a form that appears in two places and means the same thing in both, so a
reader who notices finds a second layer, and a reader who does not loses nothing.

- **Load-bearing first.** The piece reads whole without catching the echo; the main point stands on its own, and the
  easter egg adds a second layer to it.
- **True in both places.** The echo shares meaning, not only a look: a logo that is a pink drop just off the centre of
  a green target draws the deck's own colour meaning (one point, the larger field) at favicon size; a waveform's bars
  that also read as a cat's mask and whiskers make the app's mark out of its subject (sound).
- **Kinds to reach for**: a motif shared across pieces; a number that recurs with its meaning (a ring a dot runs in
  two real minutes, the loop's length); a title that reads two ways (bracketed letters: p[i]lot holds pilot, I and
  AI); a form borrowed from another field; a closing line that answers an earlier piece's opening.
- **Place them where attention already rests**: titles, logos and favicons, loading and empty states, hover cards,
  alt text, version names, the last line. A few per piece, each one earned.
- **Check each one in a sentence**: what it echoes and why that is true. If the sentence needs a stretch, cut the echo.

- **Companion documents rhyme.** Two pieces written for the same reader share a beat shape, an opening and closing
  device, one motif, one figure grammar and one colour and name per shared entity, linked across; restructure them
  together, one outline as the reference and the other mirroring it beat by beat (a peptide explainer and a chemistry doc
  basket, 2026-11-06: "the two docs should rhyme. we are learning great scientific blog writing").

## 4. Keep: make the link findable

- **Link the notes.** A memory note names its siblings with `[[name]]`, and a project's notes or README name the
  projects it borrows from, so the next session finds the match without searching.
- **Route each lesson by kind** (§1): domain facts to the project's memory, method to the general skill, taste to the
  person's style skill, through capture-lesson.
- **Keep the person's threads in one list**: the themes that recur across their work, each with where it appears, in
  their style skill (`<name>-style`, its threads section). Read it before naming, titling or designing a mark.
